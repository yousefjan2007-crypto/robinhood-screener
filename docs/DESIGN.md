# robinhood_screener — design (rebuilt 2026-09-12 as a port of the solana_screener system)

This document is the reconciled spec the code was built from: the resolved design decisions and the
module-level contracts. Where code and this document disagree, the code's docstrings and verify.py win
and this file should be corrected.

## Architecture (one paragraph)

Every 5 min the Mac dispatches the Actions workflow (GitHub cron as fallback). `run.py` advances a block cursor and reads factory/launchpad logs (exact at any cadence), adds due rechecks, the 24 h watchlist and the GT new-pools hedge, batch-enriches via Dexscreener, and runs `hard_gates` twice (pass 1: market + Multicall3-batched chain facts + ScanHood; pass 2: GT info + Blockscout + RobinX under a per-run budget, threaded). Survivors are scored, one normalized `feat` dict is built, every registered entry band is evaluated, and the champion band alone sets tier A and alerts. Events (first sighting, band fires, champion promotion) become ledger rows with a monotonic `event_seq`; every band's verdict is recorded per event; forward returns fill from **batched** snapshots; A rows drive idempotent exit signals and paper fills at router quotes; the cloud commits `data/` and deploys `docs/` every run (`latest_scan.json` is the point-in-time feature store). Inside the keeper, a 60 s ticker (`KEEPER_BOOK=1`, under the scan's lock, its four state files committed with the scan) feeds the live multi-policy book from this checkout's ledger (`LIVEBOOK_FEED_SOURCE=worktree`; the retired Mac mode read `origin/main` with git fetch + show, never pull), keyed by `(token, event_seq)`, running 16 exit policies + 2 controls off one shared fill behind a quote-integrity gate. Sundays, the improve jobs re-score exits and entry bands with day-clustered lower bounds, timing-matched controls, cumulative-trial DSR and forward-only nomination; a promotion (or a one-shot demotion) writes `champion.json` and publishes it; a headless Claude session then proposes new candidates in a temp worktree that merge only if `verify.py` is green and the diff stays inside the allowlist; one weekly summary goes to Telegram.

| Topic | Decision |
|---|---|
| Trigger / cadence | `launchd/com.yousefjan.robinhood-dispatch.plist` (StartInterval 300, exit 0) runs `gh workflow run robinhood-screener` and records the result in `dispatch.out.log`; GitHub cron `*/5 * * * *` stays as the fallback; `concurrency: {group: screener, cancel-in-progress: false}` dedups. `latest_scan.json.trigger ∈ {dispatch, schedule, manual}`. Discovery, horizons, watchlist and recheck are written to be correct at any cadence (see Discovery). Dashboard and README show the **measured** runs in the last 24 h, never "every 5 min". |
| Champion state | ONE file `selfimprove/champion.json` (tracked), schema 2: `{"schema":2, "locked":false, "exit":{champion, promoted_ts, promoted_at_alert_seq, promoted_at_ts, previous, evidence, nominee?, nominated_at_alert_seq?, nominated_ts?, failed_nominee?, demotion_judged?}, "entry_band":{champion, promoted_ts, promoted_at_event_seq, previous, evidence, nominee?, nominated_at_event_seq?, nominated_ts?, metric, failed_nominee?, demotion_judged?}, "history":[...]}`. Sole writer `selfimprove/champion.py:write_state()` (read-modify-write, tmp+`os.replace`). Cloud `run.py` reads `entry_band.champion`; cloud `paper_exec`/`alerts._plan`/`ledger` read `exit.champion`. Defaults on absence: `entry_band = "band_a_strict"`, `exit = "cfg_ladder_stop"` (the executed plan, so the paired baseline is what the system actually does; `hold_to_end` stays a challenger). `alert_seq` (exit, Mac-local `livebook.json`) and `event_seq` (entry, committed ledger) are **independent counters**; the exit nominee's forward test additionally requires `opened_ts > nominated_ts` as a guard against a rebuilt book. Names `hc_default`/`A_default`/`exit_policy`/`promoted_from` in the design docs → `band_a_strict`/`exit`/`previous`. |
| Ledger event model | Rows keyed `(token, alert_ts)`; every row carries `event_seq` (strictly increasing, minted `1+max`, `1` on an empty column, never reused), `event_kind ∈ {first_sighting, band_fire, promotion}`, `tier ∈ {A, B}`, `band` (champion band name), `fired_band` (the band whose flip opened the row; `null` for first sighting), `prior_event_seq`. Rule (`entry_lab/runtime.decide_events`): first_sighting iff the token has no ledger row; band_fire iff the token is on the watchlist, passes hard gates now, and some registered band's verdict flips True for the first time (max `BAND_MAX_EVENTS_PER_TOKEN = 4` rows per token incl. first sighting; the champion's flip always opens a row and is `event_kind=promotion`, `tier=A`); otherwise no event. **Every band's verdict is recorded at every event row** (sidecar). Promoted B rows stay in the B arm in every statistic (intention-to-treat); every table prints `promoted-B n` beside B's n; no code path filters on `promoted_ts`. Wherever the entry-lab design note says `band_events.csv`, read `event_seq` from `origin/main:data/ledger.csv`; `registered_at_event_seq`/`nominated_at_event_seq` = `max(event_seq)` there at write time. |
| Timing confound | Band statistics compare a band's picks with the **same-day, same-age-bucket** unselected pool (`BAND_AGE_BUCKETS_S = (0, 1800, 5400, 21600, 86400)` on `sighting_age_s`), and every scorecard row prints the median `sighting_age_s` of the band's selected rows. `ctl_random_band` fires at EVALUATION for a sha256-selected 10% of tokens. It formerly also waited a per-token deterministic delay `U(0, BAND_WATCH_WINDOW_S)` (sha256-derived) so its firing instants would be spread like a maturation band's; that made it inert — `run.py` records first-sighting verdicts at `sighting_age_s = 0` and controls may not open a `band_fire` row, so it returned 0 on 672 of 672 committed verdict rows. Changed 2026-09-17 (`BAND_CTL_RANDOM_CHANGED_ON`); earlier verdicts carry no evidence about it and the scorecard says so — `data/band_verdicts.csv` is not rewritten; `ctl_inverse_band` is computed on the fly in the scorecard as `champion verdict == 0` over the scoring window (never read from the sidecar). |
| Band representation | A band is `verdict(feat) -> bool | None`. `screen.hc_checks(feat) -> dict[str, bool | None]` is the ONE implementation of the HC checks (a check is `None` when its input is unknown or came from a degraded source: holders when `holders_source != "blockscout"`, template when Blockscout was dark, LP when `lp_locked_pct is None`); `screen.high_conviction` derives `misses` from it; `band_a_strict.verdict = all(hc_checks(feat).values())` with `None` if any check is `None`. No `band=` parameter, no `band_is_laxer_than_hard_gates`; `tier_for(gates_ok, verdicts, champion)` composes `gates_ok and verdict is True`, which makes a laxer band impossible by construction. Champion NA ⇒ tier B with `band_na_reason` recorded; if the champion is NA on > 50% of survivors in a run with ≥ 5 survivors, an APPARATUS notice is sent (once per `DEGRADED_ALERT_COOLDOWN_HOURS`) and `champion_na_frac` is written to `latest_scan.json`. |
| FEATURE_FIELDS | `FEATURE_FIELDS` = exactly the Dexscreener market keys + the `sources/safety.py` flat keys + `(score, first_sighting, sighting_age_s)`. the entry-lab design note's names are renamed to safety's: `is_honeypot→honeypot, round_trip_loss_pct→roundtrip_loss_pct, lp_burned_pct→lp_locked_pct, dev_holding_pct→dev_pct, blockscout_is_scam→is_scam, contract_template→template_name, tx_per_holder→tx_per_holder_total, robinx_deployer_score→creator_score` (new safety key), `scanhood_verdict/sellable` → safety keys `scanhood_verdict`, `scanhood_sellable`. `entry_lab/runtime.build_feat(market, safety, score, first_sighting, sighting_age_s)` is the single normalizer: every NaN/inf/`pd.NA` becomes `None`, every key present. Verify asserts `set(FEATURE_FIELDS) == set(feat.keys())` exactly. |
| Candidate pool | ONE registry `selfimprove/candidates/registry.json` for `kind ∈ {band, policy}`; candidates are Python modules under `selfimprove/candidates/` (`band`: `verdict(feat)`; `policy`: `POLICY = {ladder?, stop?, trail?, max_hold_s?}`); one `register.py --scan` validates and registers (import allowlist: `math`, `json`, `config`, `clf_runtime`; validated in a subprocess `python3 -I -S` with `PYTHONPATH` = repo only); one `selfimprove/trials.json` with per-family lists that only grow (`policies_ever_scored`, `bands_ever_scored`, `nominations_ever`). | Quote layer / honeypot | `sources/rpc.py` = primitives (`eth_call_ex`, `multicall3`, owner, balanceOf, totalSupply, `getAmountsOut`, logs) and `honeypot_roundtrip(token)` (two `getAmountsOut` legs, batched by Multicall3 across all pass-1 tokens; buy-leg revert ⇒ `honeypot None`, pass-through, named in `sources_dark`). **The pass-1 gate uses only `rpc.honeypot_roundtrip`.** `quotes.py` (top-level) is used exclusively by `paper_exec.py` and `livebook.py`. "Dead" for the book: **on-chain evidence first** — `absent ⇔ (V2 pair exists AND getReserves == (0,0) AND router ∈ {revert, zero}) OR (no V2 pair AND kyber == no_route AND scanhood == no_route)`; aggregators are consulted only when no V2 pair exists; any probe needed under the active branch and unanswered ⇒ `deferred`. Multicall3 (hand-rolled ABI) is core; the per-token path is the correctness reference and automatic fallback; verify pins encoder/decoder fixtures. |
| Livebook identity | Positions keyed `(token, event_seq)`; the feed opens a NEW position for a promotion or band_fire row even when the token is open as B; A/promotion rows always admitted, B admitted up to `LIVEBOOK_MAX_OPEN`; a row the band under test selected (see below) is admitted at the cap under its own sub-cap. A stratum = `event_kind == promotion OR (first_sighting AND tier == A)`; the exit gate runs on the pooled population (`IMPROVE_SCORE_STRATUM = "pooled"`) with the A stratum printed with its own n/days in every proposal; switching to A-only is a config change. Fills whose closing tick gap exceeds `LIVEBOOK_MAX_SCORABLE_GAP_S` (180 s), or with any gap above it before the close inside the decision horizon, score NaN for that policy (`n_gapped` reported). |
| Demotion | Both gates carry a pre-registered one-shot **demotion** test: after a promotion, the new champion's own forward prefix (rows after `promoted_at_*`, same floors) is judged once; exit: `own_lb <= best control own_lb` ⇒ revert to `IMPROVE_DEFAULT_EXIT_CHAMPION`; entry: `selection_lift_lb <= 0` ⇒ revert to `DEFAULT_ENTRY_BAND`; writes evidence + history, alerts DEMOTED, counts one nomination. Reversal to the default needs no positive proof, only failure to keep beating the control. |
| Paper gate for a band-under-test | The **ONE judge of the paper test** (`improve.paper_gate`, `improve.py --band-scorecard`, relayed by `summary_json` and the weekly summary's one `paper gate:` line). Pre-registered by three constants and nothing else: the band is `LIVEBOOK_BAND_UNDER_TEST`, the policy is `PAPER_GATE_POLICY` (`None` ⇒ the exit champion's executable plan), the window opens at `PAPER_GATE_WINDOW_START` (ISO-8601 UTC, stdlib-parsed; `None` ⇒ "none registered") and runs `PAPER_GATE_WINDOW_DAYS = 7` calendar days. Eligible = the Phase-4 `sidecar_true` stamp names the band AND `WINDOW_START <= opened_ts < WINDOW_START + 7 d`; the numbers come from `_score_table` on exactly those rows — **no new statistic** — with `net_lb = day_lb − policies.round_trip_cost()` on every row, policy and controls alike. **PASS** iff the window has closed (`now >= start + 7 d + LIVEBOOK_MAX_TRACK_S`) ∧ no eligible position is still open ∧ `n >= PAPER_GATE_MIN_FILLS = 20` ∧ the policy's `net_lb > 0` ∧ both exit controls' `net_lb <= 0` ∧ no inert control ∧ gapped share ≤ `BAND_MAX_GAPPED_SHARE` ∧ refused share ≤ `PAPER_GATE_MAX_REFUSED_SHARE = 0.05`; **FAIL** otherwise. **VOID** (with the whole table suppressed — no number from a broken window may be quoted) when a control's `net_lb > 0`, a control is inert, either share is exceeded, or — for a policy carrying a `flow` leg — its **tick-level** `flow_dark_share` over ARMED positions (`live_stats_dict`, the fix-round-1 quantity) exceeds 0.50: the rule was mostly not running when it mattered. `n_armed` and `flow_dark_share` are reported on **every** evaluation. Refused share = refusals / (refusals + admitted) over `data/livebook_missed.jsonl` lines inside the window whose `event_seq` carries sidecar verdict 1 for the band and whose reason is `band_under_test_full` or the entry-lag reason (both spellings are livebook's own, pinned by verify against `livebook.py`). **Unknown is not zero**: when that share cannot be MEASURED — the missed log exists but is unreadable or carries unparseable lines, or the sidecar is missing / raises while in-window refusals wait to be attributed — the window is **CAPACITY UNKNOWN ⇒ VOID** with `refused_share` None, never a pass on a numerator of 0. A missing missed log is not unknown: the file is written only when a refusal happens, so its absence is a measured zero. REPORTED, never gated: DSR and the implied Sharpe bar, the paired LB against the price-only twin, the capacity-selected band controls from the stamp, means / medians / win rates, and the in-window unstamped complement. Every verdict line carries `n_days` and, below `MIN_BOOTSTRAP_CLUSTERS`, the literal phrase **"a number, not a bound (floor 12)"** — the 7-day form was chosen knowingly and the floor is a LABEL here, not a gate. **One-shot**: `paper:<band>/<policy>@<start>` is bumped into `trials.json` once per window and `paper_verdict:…=<pass|fail|void>` once after closure (later runs print the record); changing band, policy or start is a NEW counted window, and a third window on one pair inside `BAND_RENOMINATE_COOLDOWN_DAYS` is refused. Both lines are minted on the **apply path only** — weekly.yml's Gates step, whose `trials.json` the Publish step stages. `--band-scorecard`, a dry `improve.py`, `--summary-json` and the weekly summary compute the identical verdict, print the would-be line marked "(not recorded: dry)" and write nothing: `trials.json` is tracked, so a read-only write on the Mac would diverge the tree (`run_research.sh`'s step-0 ff-merge then refuses) and would split a permanent one-shot record in two — a Mac run on an older pulled snapshot recording `=fail` while the runner records `=pass`, with no way to tell which is authoritative. **A verdict is not a promotion** — `champion.json`, `candidates/registry.json` and both Sunday gates never read it. The cost bar is **double-conservative on purpose**: the live returns already embed the quoted slippage, gas is not in the quote at all, and the $10 sizing understates real impact. |
